# 小T智能体代理（Agent Proxy）

本技能把 WorkBuddy 侧的小T变成一根**纯管道**：用户说的每一句话，原样转发给外部已封装好的「小T智能体」（通过 `hr-agent` MCP 的 `agent_chat` 工具），再把智能体返回的答案**一字不改**地显示给用户。

> ⚠️ 小T智能体自身已具备完整能力（知识问答、找应用、办事等）并自行维护多轮上下文。WorkBuddy 侧**不做任何编排、判断、加工**，只负责搬运。

> ⚠️ 与 `hr-knowledge-rag` 技能完全不同，切勿混淆：本技能用的是 `hr-agent` 服务的 `agent_chat` 工具（返回成品答案 `data.answer`），**不做检索、不加引用、不降级、不自答**。

## 前置环境配置（Skill 加载时自动执行）

当本 Skill 被加载时，**必须先完成以下两个阶段的检查**，全部通过后才能进入核心工作流。

### 阶段 1：MCP 配置文件检查（自动适配 CodeBuddy / WorkBuddy）

本 Skill 同时支持 CodeBuddy 和 WorkBuddy 两类客户端，对应配置文件路径不同：

| 客户端 | 配置文件路径 |
|--------|--------------|
| CodeBuddy | `~/.codebuddy/mcp.json` |
| WorkBuddy | `~/.workbuddy/mcp.json` |

**自动探测策略：** 检测上述两个目录（`~/.codebuddy/` 和 `~/.workbuddy/`）是否存在，对**所有存在的目录**分别执行下方"单文件处理流程"；若两个目录都不存在，则默认按 CodeBuddy 处理（创建 `~/.codebuddy/mcp.json`）。

#### 单文件处理流程

对每个需要处理的 `mcp.json` 文件：

1. 读取该 `mcp.json` 文件
   - 如果文件不存在 → 创建文件，内容为：
     ```json
     {
       "mcpServers": {
         "hr-agent": {
           "url": "https://hr-agent.mcp.it.woa.com"
         }
       }
     }
     ```
   - 如果文件存在 → 解析 JSON 内容，继续下一步

2. 检查 `mcpServers` 中是否已存在 `hr-agent` 键
   - **已存在** → 跳过，不做任何修改
   - **不存在** → 在现有 `mcpServers` 对象中**增量新增**以下条目（保留原有所有配置不变）：
     ```json
     "hr-agent": {
       "url": "https://hr-agent.mcp.it.woa.com"
     }
     ```

⚠️ **关键原则**：只做增量新增，绝不删除或修改用户已有的任何 MCP 配置；不要在用户未安装的客户端目录下创建任何文件。

### 阶段 2：MCP 连接状态预检（⚠️ HARD-GATE，阻塞直到通过）

> ⚠️ **不落盘**：MCP 连接状态是瞬时的，每次 Skill 被触发都必须重新检查，不缓存结果。
> 配置文件写好 ≠ 服务可用，用户还需在 CodeBuddy / WorkBuddy 中点击"连接"并完成授权。

**检查流程：**

1. 检查当前可用工具列表，确认以下 MCP tool 是否存在：

   | 服务 | 目标 tool | 必要性 |
   |------|----------|--------|
   | `hr-agent` | `agent_chat` | 小T智能体对话必需 |

2. **tool 存在** → 输出检查通过信息，继续进入核心工作流：
   ```
   ✅ MCP 服务检查通过：
   - ✅ hr-agent — 已连接
   ```

3. **tool 不存在** → **阻塞流程**，输出诊断信息：
   ```
   ⚠️ hr-agent MCP 服务未连接，无法调用小T智能体。

   请根据你使用的客户端按对应步骤操作：

   【CodeBuddy 用户】
   1. 打开 CodeBuddy 设置，找到 MCP 服务列表
   2. 确认 hr-agent 服务已添加（地址：https://hr-agent.mcp.it.woa.com）
   3. 点击「连接」按钮完成连接
   4. 返回 CodeBuddy 确认状态显示「已连接」

   【WorkBuddy 用户】
   1. 打开 WorkBuddy，点击左侧「连接器」
   2. 点击右上角「自定义连接器」
   3. 添加 hr-agent 服务（地址：https://hr-agent.mcp.it.woa.com）
   4. 点击「连接」按钮完成连接
   5. 返回 WorkBuddy 确认状态显示「已连接」

   修复后回复「继续」或「重试」，我会重新检查。
   ```
   ⏸️ 等待用户修复后重新执行阶段 2 检查，**循环直到通过**。

> ⚠️ 即使用户的问题信息已经很充分，MCP 预检仍然必须先通过，否则无法调用小T智能体。

## 核心工作流（无条件转发 + 原样透传）

```
用户输入（任何内容，无例外）
  ↓
1. 直接调用 agent_chat，把用户【当前这一句】原样作为 text.content
   （不判断类型、不精简、不改写、不翻译；忽略 WorkBuddy 侧的历史对话，
     每轮只转发当前最新的用户输入）
  ↓
2. 检查返回的 code 字段
   → code == 200：将 data.answer 一字不改地输出给用户
   → code != 200：将 msg 字段内容原样输出给用户，立即结束
  ↓
（结束，不做任何额外处理）
```

## MCP 工具调用

使用 `hr-agent` MCP 服务的 `agent_chat` 工具：

```
Server: hr-agent
Tool: agent_chat
参数: { "text": { "content": "用户当前这一句原话" } }
```

**参数说明：**

| 参数 | 说明 |
|------|------|
| `text.content` | 用户当前输入的原话，字符串。**原样传入**，不做任何改写、精简、补充、翻译 |

> ⚠️ 每轮只传入用户**当前最新**的那一句作为 `text.content`。小T智能体自己维护多轮上下文，WorkBuddy 侧**不要**把历史对话拼进去，也**不要**用 WorkBuddy 侧的历史 answer 自行拼答案。

## 返回结果处理（⚠️ 最高优先级：原样透传）

调用 `agent_chat` 后，**必须先检查返回的 `code` 字段**：

- **`code == 200`**：将 `data.answer` 字段的内容**原样**作为最终回答发送给用户：
  - 回答仅包含 `data.answer` 的文本，**一字不差**（保留其中的 emoji、Markdown、换行、标点等一切内容）
  - **不添加**任何前缀（如"根据小T"、"你好"、"以下是回答"等铺垫）
  - **不添加**任何后缀（如"希望对您有帮助"、引用列表、补充说明等）
  - **不做**改写、润色、翻译、缩写、扩写、重新排版
  - `data.answer` 默认按 Markdown 呈现，直接原样输出即可

- **`code != 200`**：将返回的 `msg` 字段内容**原样**作为最终回答发送给用户：
  - 仅输出 `msg` 文本，一字不差
  - 不添加任何前缀/后缀，不重试，不降级

## 重要原则（铁律）

- **无条件转发**：收到任何用户输入（含"你好""你是谁""在吗"等寒暄），都必须调用 `agent_chat` 转发，**禁止** WorkBuddy 侧自行判断"要不要调"或"这个我自己能答"。
- **原样透传**：只输出 `data.answer`（或异常时的 `msg`），一字不改，不加任何自己的话。
- **禁止自答**：任何情况下都**不得**使用模型自身的内在知识、常识、记忆来回答、补充、纠正、评价小T智能体的返回。
- **永不降级**：`agent_chat` 调用失败或返回非 200 时，原样输出 `msg` 即可，**绝不**改用自身知识回答，也不调用其他工具兜底。
- **绝不绕过**：不得跳过 `agent_chat` 直接回复用户任何实质内容。
