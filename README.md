## T专家（dsh-expert）

dsh-expert 插件：包含 **22 个分类 / 623 位专家**的名册（中文名、简介全量覆盖）。

装上以后你能做两件事：

| 做什么 | 怎么做 |
| --- | --- |
| 用专家 | 输入框打 `@` → 按分类分组的菜单 → 选中的专家作为引用 chip 进本轮对话；模型也可自行 `summon_t_expert` |
| 管名册 | 插件列表 → T专家 → **专家** 标签（看提示词 / 新建自建专家）、**分类** 标签（自建分类增删改） |
| 管技能 | 插件列表 → T专家 → **技能** 标签（关掉的技能不进模型目录，少占上下文） |

### 安装

**DSH Web / CLI**：

```bash
dsh plugin --profile web add dsh-expert
```

**DSH Desktop**：在**插件市场**里搜 `dsh-expert` 安装。

- 依赖：DSH 宿主 `>=0.1.5-rc.1`；Node `^22.19.0 || >=24`；`pnpm` 在 PATH 上。
- 装完**重启 DSH** 即可用；第一次怎么上手见下面的「快速上手」。

### 快速上手

1. **看名册**：插件列表 → T专家 的详情页里就是管理面板（**专家** / **分类** / **技能** 三个标签）。
2. **用一位专家**：输入框打 `@`，按分类挑一位，它以引用 chip 进入本轮对话；也可以直接说"让 XX 专家看看"，
   由模型调 `summon_t_expert`。

### 界面入口

| 位置 | 是什么 |
| --- | --- |
| 插件列表 → T专家 | 管理面板，**三个标签**：**专家**（提示词 / 新建自建专家）、**分类**（自建分类增删改）、**技能**（模型可调用技能的开关）。2026-09-28 起不再占「设置」里的分区 |
| 输入框 `@` | 按分类分组的专家菜单，选中即插入引用 chip |
| 输入区「T专家」按钮 | 浮层标签：**专家 / 技能**（默认停在**专家**）。分类在这里只作为专家列表的分组，没有独立标签页 —— 增删改分类请去插件信息页。两个标签都带计数（该标签里的总条数，不随搜索框变化）。原「任务」标签已在 0.3.x 迁出（T专家 不再做定时任务，由 `dsh-helper` 接管） |
| 会话标题栏徽章 | 后台任务只读面板（当前会话及其子代理的任务：状态、退出码、耗时）；只在真有任务在跑时亮起并给出数量，**面板绝不自动展开**，可拖动、位置记在本机 |

### 专家

- 名册随包发布，启动时与 `~/.t-team/` 对齐（按条目送达，见「数据目录」）。
- **自建专家**：插件列表 → T专家 → **专家** 标签 → 「＋ 新建专家」，写在 `customRoot`（默认 `~/.t-team/custom/<分类>/<slug>.md`），
  与内置名册分开 —— 内置名册升级时整棵替换，自建的不受影响；归到官方分类名下也安全（分类只是归属）。
- **自建分类**：插件列表 → T专家 → **分类** 标签 → 目录名（小写 ASCII）+ 显示名。官方分类只读；删除自建分类时若里面还有专家会被拒绝。

| 工具 | 作用 |
| --- | --- |
| `list_t_experts` | 列出已启用专家的分类与数量；传分类名可列出该分类的专家 |
| `summon_t_expert` | 召唤 1 位专家：以它的完整人格跑一个子代理并返回结果 |
| `summon_t_experts` | 并行召唤多位（最多 8 位、并发 4；部分失败仍返回成功的结果） |

### 技能开关

面板第三个标签页：**关掉的技能不再进入每次请求的 `<available_skills>` 清单**，从而少占上下文。
不改任何 `SKILL.md`，也不把文件移出扫描目录 —— 斜杠菜单里仍可手动点（与官方
`disable-model-invocation` 同一语义），重新打开立刻恢复。

- **视角**：列表默认是**全部来源的并集**（宿主全局层 / 默认 preset / 各活跃会话 / 磁盘扫描）。
  模型实际读到的是它自己那条 scope 链，两者并不相等 —— 顶部「视角」下拉切到具体来源，
  计数就变成那个视角的真实值。
- **批量**：对当前筛选结果一键启用 / 停用。
- 已带 `disable-model-invocation` 的技能显示为「原生关闭」，不会被强行打开。
- 名单在 `~/.dsh/skill-gate.json`（**沿用原插件的路径**：并入时没改，所以已有开关状态直接沿用）。
  改完下一轮模型请求即生效，不必重启。

### 数据与目录

**全部数据都在你本机**：不连任何网络服务、不做遥测；名册与中文译文都随包分发，运行时不向上游拉取。

```
~/.t-team/
├── experts/              名册：<分类>/<slug>.md 或 <分类>/<slug>/（包内快照 22 个分类、623 位；你自建的另计）
├── zh/                   中文侧车：names.json、descriptions.json、<分类>/<slug>.md
├── custom/               你在面板里自建的专家
├── source.json           名册清单（专家数 / 分类 / 更新时间）
└── .t-team-snapshot.json 上次对齐的记录（版本 / 漂移计数）
```

- 启动时**按条目**与包内快照对齐：包内新增的专家 / 译文键补齐；只读条目（`experts/`、`source.json`、
  `zh/` 的覆盖表与分区表）与包内对齐；`names.json` / `descriptions.json` **只补缺失的键**
  （你改过的键一个都不动）；你改过的译文正文保留盘上那份；包内已移除的条目只报告、不删你的文件。
- 一句话：**送得到的送到，送不到的一定出声**（日志给出数量与例子）。
  想换目录位置，用配置项 `root` / `zhRoot` / `customRoot` 覆盖。

### 常见问题

| 现象 | 原因与处理 |
| --- | --- |
| 召唤不了某位专家 | 它没在名册里、或已被停用：插件列表 → T专家 的**专家**标签里核对 |
| 更新后没看到新版本 | 重启 DSH 才生效；插件列表 → T专家 的卡片副标题带当前版本号，可核对是否已更新到新版 |

### 卸载与反馈

- **卸载**：DSH Desktop 在插件市场里卸载；CLI 用 `dsh plugin --profile web remove dsh-expert`。
  卸载不会删数据目录 `~/.t-team/`（名册与自建专家都在那儿），要清干净手动删它即可。
- **反馈与源码**：<https://github.com/jiuaiwo/dsh-expert> —— 问题请走 Issues。
